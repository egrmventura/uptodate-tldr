Build a batch orchestration runner. Goal: add a coordinated batch entrypoint (e.g. `python analyze.py --batch <spec.yaml>`) that runs the analysis pipeline across many (topic × date-window) combinations in one invocation, driven by a declarative spec listing topics and date ranges. Key constraint: batch execution must be resilient and resumable — each (topic, window) unit is isolated so one failure logs and continues rather than aborting the batch, runs respect the existing `ThreadPoolExecutor` concurrency and arXiv rate limits (bounded parallelism, backoff on 429), and re-running the same spec is idempotent via the store's `UNIQUE(topic, period_start, period_end) + INSERT OR IGNORE`. Validate with a test that drives a 3-unit batch spec through mocked ingest/analyze, asserting all three units persist, a deliberately failing unit is skipped without stopping the others, and a second identical run adds zero new rows.
